# Hyper-Connections

## 模块定位

Hyper-Connections（HC）替代普通 Transformer residual connection，在 hidden state 中
持续维护 4 份 residual streams。每个 Block 的 Attention 和 FFN 子层都分别执行一次：

```text
residual [1,S,4,4096], BF16
  -> hc_pre
       ├─ x_mixed [1,S,4096], BF16 -> RMSNorm -> Attention / MoE
       ├─ post [1,S,8], FP32
       └─ comb [1,S,16], FP32
  -> sublayer output [1,S,4096], BF16
  -> hc_post(sublayer output, residual, post, comb)
  -> next residual [1,S,4,4096], BF16
```

`hc_pre` 根据当前 4 份 residual streams 动态生成 pre mixing、post scaling 和 4×4
combination matrix。Pre mixing 把 4 份 residual streams 归约成一个 hidden state 供
子层计算；`hc_post` 再把子层 output 注入 4 份输出 streams，并通过 combination matrix
混合原 residual。

根据 [`models/config.py`](../../models/config.py)，当前固定 `hc_mult=4`、hidden
4096、flattened HC dimension 16384、mixing dimension 24、Sinkhorn iterations 20，
`rms_norm_eps` 和 `hc_eps` 均为 `1e-6`。

本文描述 [`models/hc.py`](../../models/hc.py) 的 Block-level `hc_pre_fwd` 和
`hc_post_fwd`。Embedding 负责最初的 4-stream 扩展；language-model head 使用
[`models/head.py`](../../models/head.py) 中独立的 `hc_head_fwd`，不复用本文的
pre/post 接口。

## 官方模型中的 Hyper-Connections

[`official/model.py`](../../official/model.py) 的每个 `Block` 包含 Attention 和 FFN
两套独立 HC 参数。所有参数均为 FP32：

| 官方参数组 | 参数 | Shape | 职责 |
|---|---|---:|---|
| Attention | `hc_attn_fn` | `[24,16384]` | 从 flattened residual 生成 24 个 mixing logits |
| Attention | `hc_attn_scale` | `[3]` | 分别缩放 pre、post、comb 三段 logits |
| Attention | `hc_attn_base` | `[24]` | 三段 logits 的 additive base |
| FFN | `hc_ffn_fn` | `[24,16384]` | FFN 子层独立 mixing projection |
| FFN | `hc_ffn_scale` | `[3]` | FFN pre、post、comb scale |
| FFN | `hc_ffn_base` | `[24]` | FFN pre、post、comb base |

### `Block.hc_pre`

对输入 `x ∈ BF16^[B,S,4,4096]`，官方先展平最后两维并在 FP32 中计算无 learned
weight 的 RMS scaling：

$$
x_f=\operatorname{FP32}(\operatorname{flatten}(x)),\qquad
r=\frac{1}{\sqrt{\operatorname{mean}(x_f^2)+10^{-6}}}
$$

随后执行 FP32 linear projection：

$$
m=\operatorname{Linear}(x_f,W_{hc})\cdot r,\qquad m\in\mathbb{R}^{B\times S\times24}
$$

`official/model.py` 把最后一维的分割和归一化委托给导入的
`hc_split_sinkhorn`；该函数的实现体不在当前仓库中，因此仓内代码可以直接确认其
调用参数和输出语义，但不能作为外部官方 kernel 内部步骤的独立源码证据。当前 PyPTO
实现及其 golden 按 `4 + 4 + 16` 切成三段：

$$
pre=\sigma(m_{0:4}s_0+b_{0:4})+\epsilon
$$

$$
post=2\sigma(m_{4:8}s_1+b_{4:8})
$$

$$
comb=\operatorname{Sinkhorn}
\left(\operatorname{reshape}(m_{8:24}s_2+b_{8:24},[4,4])\right)
$$

当前实现的 Sinkhorn 先按最后一维执行 softmax 并加 `hc_eps`，再做 column
normalization；其余 19 次迭代依次执行 row normalization 和 column normalization。
每次 denominator 都加 `hc_eps`。

Pre mixing output 为：

$$
x_{mixed}=\operatorname{BF16}\left(\sum_{i=0}^{3}pre_i x_i\right)
$$

官方返回 `(x_mixed, post, comb)`，其中 `post` 为 `[B,S,4]` FP32，`comb` 为
`[B,S,4,4]` FP32。

### `Block.hc_post`

对 BF16 sublayer output `z`、原始 4-stream residual `R` 和 `hc_pre` 生成的
`post/comb`，官方计算：

$$
Y_j=post_j z+\sum_{i=0}^{3}comb_{i,j}R_i
$$

结果转回 `z` 的 dtype，shape 恢复为 `[B,S,4,4096]`。需要注意输出 stream `j`
消费 `comb` 的第 `j` 列，而不是第 `j` 行。

每个官方 Block 依次执行 Attention HC pre/post 和 FFN HC pre/post；两套参数不共享。
`ParallelHead.hc_head` 只生成 pre weights 并归约 4 streams，不生成 post/comb。

## PyPTO kernel 实现

[`models/hc.py`](../../models/hc.py) 提供以下符号：

| 符号 | 类型 | 职责 |
|---|---|---|
| `hc_pre_fwd` | `@pl.jit.inline` | 生成 `x_mixed`、padded `post` 和 flattened `comb` |
| `hc_post_fwd` | `@pl.jit.inline` | 把 sublayer output 与 4-stream residual 重新组合 |
| `hc_pre_test` | `@pl.jit` | HC pre standalone 验收 wrapper |
| `hc_post_test` | `@pl.jit` | HC post standalone 验收 wrapper |
| `split_sinkhorn_golden` | PyTorch helper | 当前 Sinkhorn 分割逻辑的参考实现 |
| `golden_hc_pre` | PyTorch golden | `Block.hc_pre` 参考实现 |
| `golden_hc_post` | PyTorch golden | `Block.hc_post` 参考实现 |
| `build_hc_pre_specs` | Host spec builder | 构造实际 `S` 和 16-aligned padded scratch |
| `build_hc_post_specs` | Host spec builder | 构造动态 `S` 的 HC post tensors |

完整 Block kernel 在 Attention 子层和 FFN 子层分别直接调用一次 `hc_pre_fwd` 和
`hc_post_fwd`。Full Block 调用位于 [`models/block.py`](../../models/block.py)；selected
decode 的拆分路径位于 [`models/split_block.py`](../../models/split_block.py)。本文只
描述 HC kernel，不展开 Attention、MoE 或 split Block 的内部流程。

## 官方模块到当前实现的映射

| 官方计算 | 当前实现 | 关系/状态 |
|---|---|---|
| `x.flatten(2).float()` | `x_pad` flattened view + FP32 tile cast | 语义等价；额外 padding |
| `x.square().mean(-1)` | `K_TILE=128` 分块 square-sum × `1/16384` | 融合内联、FP32 accumulation |
| `torch.rsqrt(... + eps)` | `pl.rsqrt(..., high_precision=True)` | 直接对应 |
| `F.linear(x, hc_fn)` | `x_flat @ hc_fn_t` | 语义等价；runtime weight 已转置 |
| Linear output × RMS scale | `row_expand_mul(mix_acc, inv_rms)` | 融合内联 |
| `hc_split_sinkhorn` 的 pre/post | `hc_pre_split` vector math | 融合内联；以语义等价为目标，外部实现体不在仓内 |
| `hc_split_sinkhorn` 的 comb | 4-row softmax + alternating normalization | 融合内联；以语义等价为目标，外部实现体不在仓内 |
| `sum(pre * x, dim=2)` | `hc_pre_mix_x` | 融合内联；FP32 求和后 BF16 `rint` |
| 官方 `post [B,S,4]` | 当前 `post [B,S,8]` | 接口差异；仅前 4 列有模型语义 |
| 官方 `comb [B,S,4,4]` | 当前 `comb [B,S,16]` | Layout 差异；row-major flatten |
| `post * z + sum(comb * residual)` | `hc_post_fwd` | 直接实现；按 `comb[:,j]` 读取 |
| Attention/FFN 两套 HC | `models/block.py` 中两组直接调用 | 直接对应；参数与 scratch 分离 |
| `ParallelHead.hc_head` | `models/head.py::hc_head_fwd` | 独立专用实现；不调用 `hc_pre_fwd` |

## 数据接口

### HC pre 公共输入与输出

模型语义输入和 weights：

```text
x:        [1,S,4,4096], BF16
hc_fn_t:  [16384,24],   FP32
hc_scale: [3],          FP32
hc_base:  [24],         FP32
```

`hc_fn_t` 是官方 `[24,16384]` 参数的转置 runtime layout。Attention 与 FFN 各自传入
独立的一组 `hc_fn_t/hc_scale/hc_base`。

模型语义输出：

```text
x_mixed: [1,S,4096], BF16
post:    [1,S,8],    FP32   # only [:,:,:4] is semantic
comb:    [1,S,16],   FP32   # row-major flattened [4,4]
```

Batch 固定为 1，`S` 是动态 sequence 维。完整模型的 sequence 上限由 runtime 的
4096-token 约束决定。

### HC pre padded scratch

Host spec builder 计算：

```text
S_PAD = ceil_div(S,16) * 16
```

调用方还必须为 `hc_pre_fwd` 提供：

```text
x_pad:       [1,S_PAD,4,4096], BF16
mixes:       [1,S_PAD,32],     FP32
pre:         [1,S_PAD,8],      FP32
comb_logits: [1,S_PAD,16],     FP32
x_mixed_pad: [1,S_PAD,4096],   BF16
post_pad:    [1,S_PAD,8],      FP32
comb_pad:    [1,S_PAD,16],     FP32
```

前 `S` 行对应实际 tokens，`x_pad` 的 tail 行由 kernel 补零。`mixes` 的前 24 列是
pre/post/comb logits，后 8 列为对齐 padding；`pre` 和 `post_pad` 的前 4 列有模型
语义，后 4 列为 padding。Flattened 4×4 `comb` 已有 16 个 FP32 元素，不需要额外
channel padding。

这些 tensor 是当前 PyPTO kernel 的函数式 scratch，不是用户可观察的模型输出。
Attention HC 与 FFN HC 在同一 Block kernel 中使用不同 scratch，避免同一调用内发生
读写别名。

### HC post 接口

```text
x:        [1,S,4096],   BF16
residual: [1,S,4,4096], BF16
post:     [1,S,8],      FP32
comb:     [1,S,16],     FP32
out:      [1,S,4,4096], BF16
```

`hc_post_fwd` 只读取 `post[:,:,:4]`。`comb` 按 `[input_stream,output_stream]` 的
row-major 顺序 flatten。HC post 不接收 `S_PAD` scratch，直接处理实际动态 `S`。

### State 与 runtime 边界

HC 没有跨 layer 或跨 decode step 的持久 state。`post` 和 `comb` 是一次子层内部从
`hc_pre` 传给 `hc_post` 的临时数据：

- Full Block 中，Attention 和 FFN 的 `post/comb` 都在同一个 kernel dispatch 内生成
  和消费；
- Split decode 中，FFN `post/comb` 作为 pre-MoE kernel output 保持在 device，随后由
  post-MoE kernel 消费；它们不会回传 host，也不会跨 decode step 保留。

[`serving/weight_loader.py`](../../serving/weight_loader.py) 将 Attention/FFN 两套 HC
weights 转为最终 FP32 runtime layout；这些 `RuntimeWeight` 首次 materialize 后作为
fixed weights 常驻 device。Scratch 和 `post/comb` 属于当前 dispatch 的 device
intermediate，不属于 weight cache。

## 实现方式

### Sequence 与 channel padding

`hc_pre_fwd` 的核心计算固定使用 16-token tile。Kernel 先把实际 `x` 拷贝到
`x_pad[:,:S]`，把 `[S,S_PAD)` 行补零，之后所有 linear、split、Sinkhorn 和 pre
mixing 都只处理完整 tile，最后仅把前 `S` 行拷回公共 outputs。这样 aligned 和
non-aligned sequence lengths 使用同一核心路径。

24-wide mixing output 在 GM scratch 中扩展为 32 列；4-wide pre/post 扩展为 8 列。
这些 padding 满足当前 vector load/store 的访问宽度要求，不改变有效列的数学语义。

### RMS-scaled mixing projection

对每个 16-token tile，kernel 沿 flattened 16384 channels 以 `K_TILE=128` pipeline：

1. BF16 `x` 转 FP32 并累加 square sum；
2. 同时执行 `x @ hc_fn_t` 的 FP32 matmul accumulation；
3. square sum 乘 `1/16384`、加 `1e-6`，用 high-precision `rsqrt` 得到 RMS scale；
4. 对 projection 的每一行乘对应 RMS scale，写入 `[S_PAD,32]` `mixes`。

该 normalization 不包含 RMSNorm learned weight，也不调用 `models/rmsnorm.py`；它是
HC mixing projection 内部的无参数归一化。

### Pre、post 与 Sinkhorn

`hc_pre_split` 从 `mixes` 读取 `4 + 4 + 16` 个有效 logits，在 FP32 中应用三项
`hc_scale` 和对应 `hc_base`。Pre 使用 `sigmoid + hc_eps`，post 使用
`2 * sigmoid`。

Comb logits 先物化到 `[S_PAD,16]` GM scratch，再以 4 个 `[16,8]` padded row tile
重新加载。每行执行稳定 softmax 后加 `hc_eps`；随后完成一次 column normalization，
再执行 19 轮 row/column normalization。最终 4 行按 row-major 顺序写入
`comb_pad`。

`comb_logits` 是 Sinkhorn row reload 的中间存储，不是对外输出。当前实现不会检查
最终 row/column sums；迭代次数和 epsilon 均来自固定模型配置。

### HC pre mixing

Kernel 按 16 tokens × 512 hidden channels 处理 `pre * x`。4 份 BF16 residual streams
分别转成 FP32，与对应 FP32 pre scalar 相乘并求和；结果以 `rint` 转成 BF16
`x_mixed_pad`。4096 hidden channels 共分成 8 个 `D_TILE=512` blocks。

### HC post mixing

`hc_post_fwd` 不做 sequence padding。它逐 token、逐 output stream `j` 读取
`post_j` 和 `comb_{0,j}..comb_{3,j}`，再按 512 hidden channels 分块把 BF16 sublayer
output 与 residual streams 转成 FP32：

$$
out_j=post_j\cdot x+
comb_{0,j}R_0+comb_{1,j}R_1+comb_{2,j}R_2+comb_{3,j}R_3
$$

每个 output tile 最后以 `rint` 转成 BF16。HC post 不执行额外 normalization。

## 实现差异与限制

- 当前 kernel 固定支持 `B=1`、`hc_mult=4`、hidden 4096、mixing dimension 24，不是
  任意尺寸的 HC API；
- HC pre 要求调用方提供 `S_PAD=ceil_div(S,16)*16` 的完整 scratch，HC post 只使用
  实际动态 `S`；
- 当前 runtime `post` shape 为 `[1,S,8]`，仅前 4 列有模型语义；官方 shape 为
  `[1,S,4]`；
- 当前 `comb` 使用 `[1,S,16]` row-major flattened layout，官方使用 `[1,S,4,4]`；
- Sinkhorn iterations 固定为 20，`rms_norm_eps` 和 `hc_eps` 固定为 `1e-6`；
- `hc_pre_fwd` 使用额外 GM scratch 物化 padded input、mixing logits 和 Sinkhorn
  intermediates；这些不是官方 API 的 outputs；
- Attention 与 FFN HC 参数和 scratch 始终分离，不共享一次 `hc_pre` 的 post/comb；
- HC 不维护跨层或跨 step state，split decode 中跨 kernel 的 post/comb 也只在当前层、
  当前 step 内有效；
- 本文的 `hc_pre_fwd/hc_post_fwd` 不实现 `ParallelHead.hc_head`；head 使用独立的
  pre-only kernel；
- 当前 Block HC 是单卡逻辑，本身不包含分布式通信。

## Golden 参考实现

`models/hc.py::split_sinkhorn_golden` 用 PyTorch 实现当前 pre/post 分割和 20 次
Sinkhorn normalization。`golden_hc_pre` 从未 padding 的 BF16 `x` 和 FP32 HC weights
开始：在 FP32 中执行 flattened RMS scaling、linear、split/Sinkhorn 和 4-stream
mixing，再把 `x_mixed` 转为 BF16。

Golden 不模拟 sequence 或 channel padding。若 `post` output 的最后一维为 `HC_PAD=8`，
它只填写前 4 列并把 padding 列置零；`comb` reshape 为 `[B,S,16]`。Standalone spec
包含 `mixes/pre` scratch 时，golden 只填写前 `S` 行及相应有效 channels。

`golden_hc_post` 只消费 padded `post` 的前 4 列，把 flattened `comb` 恢复为
`[B,S,4,4]`，在 FP32 中执行官方组合公式，最后按 `out` dtype 转为 BF16。

## 精度验收标准

HC pre 的三个模型输出分别使用：

| 输出 | 验收方式 | Absolute tolerance | Relative tolerance | 允许超出容差的元素比例 |
|---|---|---:|---:|---:|
| `x_mixed` | `ratio_allclose` | `1e-4` | `1/128` | `0.001` |
| `post` | `ratio_allclose` | `2.5e-5` | `5e-3` | `0.001` |
| `comb` | `ratio_allclose` | `2.5e-5` | `5e-3` | `0.001` |

HC post：

| 输出 | 验收方式 | Absolute tolerance | Relative tolerance | 允许超出容差的元素比例 |
|---|---|---:|---:|---:|
| `out` | `ratio_allclose` | `1e-4` | `1/128` | `0.001` |

所有输出最多允许 0.1% 元素超出相应逐元素容差。Actual output 中出现任何 NaN 或
Inf 都会直接判为不合法。

## 验收方法

在 Ascend A2/A3 实机上同时验证 HC pre 与 post 的 aligned sequence：

```bash
python models/hc.py \
  --platform a2a3 \
  --device 0 \
  --seq-len 16 \
  --case all
```

使用非 16 对齐 sequence length 验证 HC pre 的 padding/copy-out 和 HC post 的动态
sequence 路径：

```bash
python models/hc.py \
  --platform a2a3 \
  --device 0 \
  --seq-len 13 \
  --case all
```

可使用 `--case pre` 或 `--case post` 单独选择路径；增加 `--compile-only` 可仅检查
编译，增加 `--enable-l2-swimlane` 会把相应选项传入 PyPTO `RunConfig`。

Host-side HC golden 与官方 Block composition 的比较可运行：

```bash
pytest -q tests/models/test_hc.py
```

[`test_hc.py`](../../tests/models/test_hc.py) 使用缩小 hidden shape、`hc_mult=4` 和 3

`Block.hc_pre/hc_post`。测试将官方模块引用的 `hc_split_sinkhorn` 替换为当前
`split_sinkhorn_golden`，因此覆盖 Block 组合公式、参数布局和 dtype 边界，但不是对
外部官方 Sinkhorn kernel 的独立交叉实现比较。该 host test 不执行 PyPTO NPU
kernel，不能替代 standalone 实机验收。

### Block 集成

- [`test_block.py`](../../tests/models/test_block.py) 覆盖 Attention/FFN 两套 HC 参数、

  拆分后 FFN post/comb 跨 kernel 传递和最终 HC post；

  HC function weight 的 FP32 transposed layout 和重复读取时的 runtime weight identity。
